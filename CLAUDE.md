## What we're building

**SmartShopper** is a mobile-first grocery list and price comparison app. Users build a shopping list, scan barcodes or use AI vision to identify products, see prices across all supported stores in real time, and contribute receipt data to keep prices accurate. The killer feature is the price comparison popup — scan or tap any item, see where it's cheapest right now.

The data backbone is a blend of:
1. Open Food Facts (free product database)
2. Admin-curated weekly circulars (parsed via Claude API)
3. User-contributed receipt scans (OCR'd, matched to products)
4. Manual user price entries

## Tech stack

| Layer | Tech | Why |
|---|---|---|
| Mobile | Expo SDK + React Native + TypeScript | One codebase, iOS + Android, all native APIs we need |
| Routing | Expo Router | File-based, type-safe |
| State | Zustand + React Query | Lightweight, no boilerplate, great cache invalidation |
| Styling | NativeWind (Tailwind for RN) | Fast iteration, consistent design tokens |
| Backend | Supabase | Postgres + Auth + Storage + Edge Functions, generous free tier |
| Database | Postgres (via Supabase) | Relational, RLS-protected, SQL-first |
| Camera | react-native-vision-camera | High performance, ML Kit integration |
| Barcode | vision-camera-code-scanner | Built on ML Kit, free, fast |
| AI Vision | Google ML Kit (on-device) | Free, no per-scan cost |
| OCR (receipts) | ML Kit Text Recognition | Free, on-device |
| Background removal | rembg (open source, self-hosted) | Apache 2.0, runs as Supabase Edge Function |
| Circular parsing | Claude API (vision) | Admin-only batch job, low cost |
| Image rendering | expo-image | Disk cache, blurhash, performance |
| Animation | react-native-reanimated | UI-thread animations, never drops frames |
| Admin panel | Next.js + Supabase | Web-based, deployed on Vercel free tier |

## Critical rules — these are non-negotiable

### Performance
1. **Always use `expo-image`, never the default `Image`.** No exceptions. Default Image has no cache and tanks performance.
2. **All animations via `react-native-reanimated`.** No `Animated` from react-native, no JS-thread animation libraries.
3. **All scrollable lists use `FlatList` or `FlashList`.** Never `ScrollView` + `.map()` for variable-length data.
4. **No fixed pixel widths/heights for layout.** Use `flex`, percentages, or `useWindowDimensions()`.

### Layout
5. **Every screen wrapped in `SafeAreaView`** from `react-native-safe-area-context`. The default `SafeAreaView` from React Native is deprecated.
6. **Tap targets minimum 44×44pt.** Use `hitSlop` if visual is smaller.
7. **Design target is iPhone SE width (375px).** If it works on SE, it works everywhere. Test there first.

### Data & API
8. **No direct fetch() calls in components.** All data goes through React Query hooks in `mobile/hooks/`.
9. **All Supabase queries are typed.** Run `npx supabase gen types typescript` after every schema change.
10. **Never expose the Supabase service role key in the mobile app.** Anon key only. Admin operations go through Edge Functions.

### Code quality
11. **TypeScript `strict: true` always.** No `any`, no `@ts-ignore` without a `// REASON:` comment.
12. **No console.log in committed code.** Use a logger utility. Strip debug logs before commit.
13. **Components in separate files.** One default export per file. File name = component name.
14. **No inline styles for theme values.** Use NativeWind classes or design tokens from `constants/`.

### Architecture
15. **Mobile and admin share types via `mobile/types/database.ts`** (auto-generated by Supabase CLI).
16. **Edge Functions for sensitive or compute-heavy ops** — circular parsing, background removal, batch product matching. Never do these client-side.
17. **RLS policies on every table.** No table without RLS. Default deny, explicit allow.

## Commands

```bash
# Mobile dev
cd mobile
npm install
npx expo start              # Start dev server (scan QR with Expo Go)
npx expo start --ios        # Open iOS simulator
npx expo start --android    # Open Android emulator

# Database
npx supabase start          # Start local Supabase
npx supabase db reset       # Reset local DB and re-run migrations
npx supabase gen types typescript --local > mobile/types/database.ts

# Admin panel
cd admin
npm install
npm run dev

# Type check (run before every commit)
cd mobile && npm run typecheck
cd admin && npm run typecheck
```

## Session protocol — how to work in this codebase

When starting a Claude Code session:

1. **Orient first.** Read this file, then the relevant docs in `/docs`. Summarize the goal in your own words before writing code.
2. **One feature per session.** Don't combine unrelated changes. Small, focused, committable units.
3. **Branch off main.** `git checkout -b feature/short-description`.
4. **Test on a real device when touching camera, GPS, or storage.** Simulators lie about these.
5. **Run typecheck before committing.** No type errors land on main.
6. **Commit message format:** `feat(scope): description` / `fix(scope): description` / `chore(scope): description`.
7. **Update `docs/DECISIONS.md`** when making any non-obvious architectural choice.

## Known gotchas

- **Expo Go does not support all native modules.** `react-native-vision-camera` requires a development build (`npx expo run:ios` / `npx expo run:android`). Plan for this from session 7 onward.
- **Supabase RLS bypasses anonymous reads if not configured.** Test as anon user explicitly when adding new tables.
- **iOS simulator camera shows a fake feed.** Always test scanning features on a real device.
- **Open Food Facts has rate limits** (100 req/min for anonymous). Cache aggressively.
- **Receipt OCR results are messy.** Always store raw text alongside parsed data so we can re-match later.
- **GPS geofencing on Android requires foreground service permission for background detection.** For now, only foreground detection — no background tracking.

## What this project is NOT

To prevent scope creep:
- ❌ Not a delivery service. We don't fulfill orders.
- ❌ Not a coupon clipper. We may surface promo prices but don't manage coupons.
- ❌ Not a recipe app. Adding recipes is post-MVP at earliest.
- ❌ Not a meal planner. Same.
- ❌ Not a multi-language app at launch. English only for MVP.
- ❌ Not a global app. Caribbean / Trinidad & Tobago focus first; expansion later.

If the user asks for something on this list, redirect to a feature that's in scope.
